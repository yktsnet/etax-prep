# 規約

## 依存を増やさない

ビルドステップも npm 依存も持たない。素の ESM をブラウザと Node がそのまま読む。Lucide のアイコンは必要な分だけ `public/icons.js` に SVG として同梱してあり、CDN へ出ない。

新しいライブラリを足す前に、それが無くて済まないかを先に検討する。この規模では大抵済む。

## 業務ロジックを実行環境から切り離す

`core/` は Node にも Workers にも依存しない。ファイルシステムやプロセス環境を触るのは `store-local.mjs` と `dev/server.mjs` だけ。

新しい API を足すときは `core/api.mjs` に書く。`dev/server.mjs` や `functions/` には書かない。

## 集計は純関数にする

`core/aggregate.mjs` と `core/tax.mjs` の関数は入力から出力を返すだけにし、取得も保存もしない。テストが書けるのはこの性質による。

## 年に依存する数値は設定に出す

税率・控除額・上限は `config/tax-<年>.json` に置き、計算コードは年を知らない。金額のしきい値（10万・30万など）も同様に扱えるものは設定へ寄せる。

## 記録を消さない

取消は `void` フラグ、証憑の取り外しは `detachedReceipts` への退避で表す。行やファイルを削除する実装を書かない。電子帳簿保存法が訂正・削除の履歴を求めるため。

## UI

- ダーク専用。`prefers-color-scheme` の分岐を書かない
- 色を持つのはチャートだけ。UI クロームは無彩色＋抑えたアクセント1色に留める
- チャートの配色は `dataviz` skill の検証済みパレットに従う。色を足すときは `validate_palette.js` を通す
- アイコンは Lucide。絵文字を UI に使わない
- CSS の色は必ず `:root` のトークン経由で参照する。生の16進をルール中に書かない

## 命名

- 保存されるデータのキーは英語、UI に出る文字列は日本語
- 勘定科目は決算書の科目名をそのまま使う。独自の言い換えをしない

## コメント

WHAT は書かない。非自明な WHY（制度上の制約・回避策）だけを書く。
