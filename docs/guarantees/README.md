# Guarantee Ledger

このリポが外へ約束している振る舞いと、それを守るテストの一覧である。約束が破れればテストが落ちるので、ここに書いたことは気づかないうちに実装とずれていかない。**ここに載っていない振る舞いは約束ではなく、予告なく変わりうる。**
対象は `core/` の純関数（集計・税計算）と、HTTP API および保存先の応答である。UI（`public/`）の見た目と操作は対象外で、目視で確かめる。この台帳の地位は [設計判断の記録](../design-decisions.md) と同格である。

- 目的: いま何を約束しているかを1か所で読む。変更の前に、破ってはいけない約束をここから引く。テストの無い約束を Gaps に残す
- 分け方: 約束の対象（`core/` のモジュール・HTTP API・保存先の実装）ごとに1ファイル。テストファイルや Issue の単位では分けない。新しい対象を作ったときだけファイルを足す
- 書き方: 各ファイルに「保証｜対応テスト」の表を置き、1行に約束を1つ、宣言文で書く。出典・経緯・設計の理由は書かない（設計判断の記録が持つ）。UI の見た目と、手で確かめる操作は載せない。約束が10行以上のファイルは、内容のまとまりで `##` の見出しを立て、見出しごとに3行以上の表を置く（ファイルは分けない）。10行未満のファイルには見出しを置かない
- 引き方: 変更の前に、その対象のファイルを開いて守る約束を読む。テストが落ちたら、テストの名前で台帳を検索すると、破れた約束の行が見つかる。約束が守られていることは、全テストを流す CI が確かめる
- 運用: 変更の前にこの README を読み、変更が触れるファイルから「維持する保証」を引く。約束を足す・変える・消すときは、承認を受けた保証節の文のまま、該当するファイルの表に行を足す・直す・消し、対応テストも同じ変更で直す。英語版（`*.en.md`）も同じ変更で合わせる。Issue や作業ごとにファイルや節を起こさない。テストの無い約束は Gaps に書き、テストを足したら移す。乖離は `guarantee-audit` で棚卸しする
